01 / 集成现状03
成本结构

点对点：链路的数量是平方级的

同样是 6 个系统互相打通，两种做法要维护的链路数量差 2.5 倍；到 8 个系统，差距拉到 3.5 倍。

手工点对点 · 系统两两直连
6 个系统 = 15 条链路 · 8 个系统 = 28 条
经中台枢纽 · 星型接入
6 个系统 = 6 条链路 · 8 个系统 = 8 条
关键差别：点对点方案每新增 1 个系统，要新增 N 条链路并重测 N 个对接方；枢纽方案只新增 1 条接入，其余系统完全不动。
集成中台 · 产品介绍04
代价拆解

真正的成本，发生在连线之后

连线数量只是账面成本。以下四项才是集成方案上线后持续消耗团队精力的地方。

交付慢：每条链路都是一次小项目

取数口径确认、接口开发、双方联调、测试验证，每一步都要两个团队同时在场。

业务后果：新系统上线要排期等待，IT 变成瓶颈。

故障黑盒：失败之后只能人工补

同步失败通常只留下日志。没有失败数据的滞留区，没有原样重放，也没有可回退的版本快照。

业务后果：数据不一致要靠人肉核对，问题反复发生。

口径散落：字段映射写死在代码里

同一个"客户编码"在不同系统的转换规则，分散在各系统的代码与配置中，没有统一视图。

业务后果：改一个口径要动多个系统，还说不清谁改的。

身份孤岛：账号各管一套

员工入职要逐个系统开号，离职要逐个系统关闭；跨系统跳转要重新登录，权限变更无审计。

业务后果：离职账号残留是合规风险，跨系统体验差。

02 / 定位与能力06
产品定位

它是枢纽，不是第 N+1 个业务系统

中台自身不承载业务，只提供集成服务。它把"系统之间怎么连"这件事，从各业务系统的代码里抽出来，集中成可配置、可监控、可审计的能力。

控制台与 API 分离

运营在控制台完成资产登记、任务配置、授权与监控；业务方只通过 API 调用能力，不接触控制台。

面向集成商的一把钥匙

对外开放服务采用 API Key 门面。集成商用 Key 接入应用、数据、消息与身份，无需了解中台内部结构。

资源可见性可控

密钥只能看见"自己创建的"和"被运营指派给它"的资产，天然支持多集成商共存的隔离。

一句话价值主张：接入中台之后，你的业务系统需要对接的不是 N 个其他系统，而是 1 套集成能力。
说明：本页描述的是产品定位，非部署形态承诺。部署方式见第 20 页。

能力 02 / 映射与转换

把口径从代码里拿出来，放进可审计的配置

映射规则是集成项目里最容易失控的部分。这里提供的是配置化、可预览、可复用的映射模型。

映射与转换能力

直接映射类型转换 默认值填充自定义表达式 状态码映射

内置字符串处理（去空格、大小写、拼接、截取、替换）、编解码、数值与日期转换等常用转换，复杂场景可用自定义表达式。

嵌套字段通过点号路径读写，不必为层级结构单独写适配代码。

预置同步模板

内置 5 套用户同步模板，覆盖扁平字段、HR、AD 域、钉钉、企业微信等典型形态，包含字段对应关系与状态映射规则。

通用用户同步HR → OA AD 域 → 业务系统钉钉 → 业务系统 企业微信 → 业务系统
价值：常规同步场景不必从零配映射，直接套模板再按需覆盖。

落库之前先看结果

映射预览会先用真实数据跑一遍转换，把"源字段 → 目标字段"的实际结果摊开给你确认，再进入正式写入。

业务后果：口径错配在预览阶段就被拦住，而不是数据写坏之后才发现。

状态码不是字符串问题

在职 / 离职 / 试用 / 禁用这类业务语义，用一组显式映射规则表达，而不是散落在各处的 if-else。

业务后果：人员状态口径统一，下游系统不再各自解释。

能力 03 / 执行引擎

失败不是异常情况，是常态——所以我们按常态设计

集成方案能不能托付，看的不是成功路径跑多快，而是失败之后能不能定位、能不能恢复、能不能追溯。

可编排：DAG 多步任务

一个任务可拆成多个步骤，用依赖关系声明先后顺序，在任务页用画布完成编排；运行后在执行监控里逐步查看状态。

价值：复杂同步不再塞进一个巨型脚本。

可恢复：死信与人工决裁

失败数据进入死信区并做脱敏处理。可原样重处理、可忽略，也可以修正字段后重新落库。

价值：坏数据不再只能靠人工补数。

可追溯：快照与字段审计

保留版本快照，可按需回滚；字段级变更留痕，能回答"这个值是谁、什么时候改的"。

价值：数据被改坏时可回退，责任可界定。

不把空跑当成功

抽取 0 行不会被记成一次成功执行。静默的数据断流会被暴露出来。

重试与回执

可配置失败重试次数与间隔；任务完成可回调通知业务系统，不必轮询。

防回环

双向同步场景下携带来源标记与跳数控制，避免数据在两个系统之间无限反弹。

能力 04 / 身份与应用集成

一次登录，跨系统通行

把应用纳管进中台，由中台统一签发身份凭证，业务系统之间不再各自维护一套账号体系。

统一登录与跨系统跳转

支持 JWT 与 Ticket 两种凭证形态，"来源系统 → 中台 → 目标系统"三段式免登跳转，目标系统只需实现一次凭证校验。

业务后果：用户不再为跳转系统重复输密码，体验与安全同时改善。

标准协议双支持

既支持 OAuth2 授权码 + PKCE，也支持 SAML 单点登录；平台自身同时可作为授权服务器对外提供授权能力。

业务后果：新老系统都能纳入同一登录体系，不必为协议差异做取舍。

SAML 不放过未签名断言

接入 SAML 需要配置 IdP 证书，ACS 环节强制校验 XML 数字签名。未签名的断言会被直接拒绝，同时校验响应关联性、受众与有效期后才建立会话。

价值：这是安全团队会重点追问的一条，建议在演示时现场打开配置项。

会话可看、可吊销、可审计

提供活跃会话列表与吊销操作，登录行为进入审计日志。

业务后果：账号异常时有处置手段，事后有记录可查。

能力 05 / 组织与用户同步

把人理顺：从通讯录到部门树

组织数据是所有权限体系的地基。中台把"从各平台拉通讯录、还原成部门树、再同步到业务系统"变成一条可重复执行的任务。

多来源拉取

可从钉钉、企业微信、AD 域、LDAP 拉取用户与部门。既可作为独立的通讯录同步任务，也可作为普通数据同步任务的抽取源。

部门树还原

同步结果落成部门层级与"人-部门"关系，可按任务查询完整组织树，供下游系统直接消费。

模板化 + 状态映射

5 套预置模板覆盖典型场景；人员状态（在职、离职、试用期、禁用）通过显式规则映射。

敏感字段脱敏

支持多种脱敏规则，并能按字段名称智能识别手机号、证件号、银行卡等敏感项。

价值：组织数据常含个人信息，脱敏可在任务层统一策略，而不是靠各系统自觉。

入职离职自动流转

状态变化随同步自动落到下游系统，减少"人走了账号还在"的残留。

业务后果：账号生命周期与人事流程对齐，降低合规风险。

能力 06 / 开放服务

把集成能力变成一把可以发放的钥匙

这是本产品在设计上最有辨识度的一点：集成能力不是只能由内部团队使用，而是可以标准化地交付给外部集成商。

自助开通 + 受控授权

集成商可通过公开接口自助开通沙箱密钥；正式资源由运营在控制台登记后指派。密钥完整值只返回一次。

IP 白名单每分钟限流 失败告警邮箱 / Webhook密钥轮换与吊销
业务后果：生态接入从"一个对接项目"降级为"发一个 Key"。

可见性边界清晰

密钥只能访问"本凭证创建的"与"运营明确指派给它的"应用、数据源、任务与执行记录。未指派的控制台资产对密钥不可见。

业务后果：多集成商可共享一套中台，而业务数据互不可见。

对接成本低

提供 OpenAPI 3.0 规范与 Swagger UI，可直接生成客户端；官方 Python 与 TypeScript SDK 开箱可用。

入口双向

既能主动调用中台能力，也能通过入站 Webhook 把数据推进来。

重放安全

支持幂等键，网络重试不会造成数据重复写入。

演示建议：现场用一段脚本完成"自助开通密钥 → 登记数据源 → 触发同步 → 查看执行记录"的闭环，比逐条讲接口更有说服力。

能力 07 / 可观测与治理

看得见，才敢把生产数据托付出去

集成中台处在数据链路的关键位置，它的可观测性直接决定团队敢不敢用它承载核心数据。

仪表盘

汇总统计与执行趋势，任务健康度一眼可见。

标准指标

提供 Prometheus 格式指标接口，可接入你现有的监控与告警体系，不必另建一套。

操作审计

增删改操作全部留痕，配合字段级变更审计形成完整链路。

多环境隔离

区分开发 / 预发 / 生产环境，并支持按 Workspace 维度隔离，请求维度即可切换。

执行记录不是一行日志

每条执行记录包含状态、耗时、影响行数与失败原因；DAG 任务可下钻到每个步骤的状态。

价值：排障从"翻日志猜原因"变成"看记录定位步骤"。

告警走你已有的通道

任务失败可配置邮件告警；密钥层面还可配置失败通知的邮箱或 Webhook。

价值：不需要为了这个系统新建一套运维流程。

Next Step

建议的下一步：把验证标准先写下来

一次定向演示只能建立信心，真正的决策依据来自你们自己数据上的验证结果。

第一步 · 技术对齐（约 30 分钟）

确认你们的环境组成、必须打通的系统清单、安全评审要求与关键角色。会后产出一份定向演示脚本。

第二步 · 定向演示（约 45 分钟）

围绕你们指定的两到三条真实链路演示，包含一次刻意制造的失败与恢复过程。

第三步 · 小范围验证（2–3 周）

选定一条真实链路，在开始前书面确认通过/不通过的标准、时间点与决策人。

我们主动提醒：验证范围要克制。聚焦一条链路做到结论明确，比铺开五条链路后得到一个模糊结论有价值得多。范围外的新需求建议放进第二阶段。

本次沟通不涉及

以下方向目前在产品中尚未落地，本次不作为能力介绍：变更数据捕获（CDC / binlog 级实时同步）、Kubernetes 编排与自动扩缩容、超大规模文件批量传输、对外 SLA 状态页与按行计费。

26 类连接器、ETL 与 DAG 编排、死信与快照回滚、字段级审计、SSO 四种协议、组织同步、开放 API 门面、Prometheus 指标与全量审计。
